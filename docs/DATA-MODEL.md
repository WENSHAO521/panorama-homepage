# Static Data Architecture

No database, no CMS — every content type is a version-controlled file
under `web/src/data/` (or, for future long-form content, an Astro
Content Collection under `web/src/content/` — see §Content Collections
below). Types live in `web/src/types/`.

## Journals — `web/src/data/journals.json`

Schema: `web/src/types/journal.ts` (`Journal`). **24 real journals**,
migrated from the legacy `data/journals.json` (harvested 2026-09-12
from the journals' own OJS home pages) — not fabricated. Field
mapping/decisions:

- `slug` is a **new**, clean, lowercase-kebab identifier for this
  site's own `/journals/<slug>/` route (e.g. `pfr`, `hncbt`). It is
  distinct from the legacy `journalUrl`/`submissionUrl`, which keep
  their **real, unmodified** OJS path segments — including two that
  are objectively inconsistent (`CSSR`'s OJS path is lowercase `cssr`;
  `GRHAS`'s OJS path is the unrelated-looking `files`). Those
  inconsistencies are carried forward verbatim with a `note` field
  flagging them, rather than silently "corrected" into a URL that
  might not actually resolve.
- `openAccess: true` for all 24 — inferred from PSG's editorial
  language ("peer-reviewed, open-access") repeated across most journal
  descriptions in the source data, not confirmed individually
  per-journal. Documented here as an inference, not a confirmed fact
  per journal — a Round 6 content check should verify it against each
  journal's real OJS policy page.
- `frequency`/`eissn` are omitted (left `undefined`) everywhere — no
  legacy source gave real values, and the brief prohibits fabricating
  metadata (§25).
- Two journals carry a `note` documenting a cover/id filename mismatch
  found in the source data: `PEMR`'s cover file is `REMR.png`;
  `GRHAS`'s cover file is `GRAHS.png`. Not silently fixed.
- `GPPGR` is kept with `status: "retired"` (not deleted) and a note
  explaining it was succeeded by `GGSR` — matches the legacy data's own
  retirement note and the project brief's "do not silently delete
  historically indexed URLs" principle (§29), extended here to data,
  not just routes.
- 3 journals (`HNCBT`, `JPOII`, `GGSR`) have `description: null` — the
  legacy source itself notes these are new journals still awaiting
  publisher copy. Left `null`, not filled in with invented text.

## Imprints — `web/src/data/imprints.json`

Schema: `web/src/types/imprint.ts` (`Imprint`). 5 entries (Ridgeline,
Health Nexus, Verdant Science, Charter, Threnody), `scope` taken
verbatim from the legacy `subBrands` table. `accent` stores a CSS
custom-property **reference** (e.g. `"var(--imprint-ridgeline)"`), not
a raw hex — see docs/DESIGN-SYSTEM.md.

## Books — `web/src/data/books.json`

Schema: `web/src/types/book.ts` (`Book`). **Empty array.** The
repository audit found no institutional book records anywhere in the
legacy site or its data files — `books.panorama-sg.com` is confirmed
as an independent platform (project brief §34), and PSG's own book
catalogue may live there rather than in this repo. Nothing was
fabricated to fill the gap; `/books/` renders an explicit empty state
saying so.

## Partners — `web/src/data/partners.json`

Schema: `web/src/types/partner.ts` (`Partner`). 19 entries: 17
indexing/archiving services with real, independently-known public URLs
(Crossref, DOI Foundation, Dimensions, Google Scholar, ISNI, ISSN,
LOCKSS, CLOCKSS, OpenAIRE, OpenAlex, PKP, Semantic Scholar, Zenodo,
BASE, ZDB, DNB, PLOS OA) plus 2 institutional partners whose real
identity/URL could **not** be confirmed from the legacy repository
(Taoist Association of Korea — mark preserved, but no official URL was
found anywhere in the legacy repository; and an entirely unlabeled
"library-logo.png"). Both are explicitly marked `url: null` with a
`notes` field instructing against production display until identified
— see docs/ASSET-AUDIT.md.

## Navigation — `web/src/data/navigation.ts`

Schema: `web/src/types/navigation.ts` (`NavItem`). Three exported
arrays (`primaryNav`, `utilityNav`, `footerNav`) — the single source
every future nav component must read from. See
docs/INFORMATION-ARCHITECTURE.md.

## Redirects — `web/src/data/redirects.json`

Schema: `web/src/types/navigation.ts` (`RedirectRule`). Generated by
[`scripts/build_redirects.py`](../scripts/build_redirects.py) from a
full enumeration of the 119 legacy page URLs (118 rules — `404.html`
is excluded as it isn't a redirect target). **This is an audit, not
live redirect configuration** — see docs/MIGRATION.md for the counts
and what Round 14 still needs to decide before these become real
Cloudflare redirect rules.

## Site facts — `web/src/data/site.ts`

Organisation name, email, registered address, and the 6-entry
`externalSystems` map (journals/books/research/posi/profiles/
credentials subdomains) — every value taken verbatim from the legacy
site's own `Organization` JSON-LD (`about.html`, read via
`git show HEAD:about.html` since the file no longer exists on disk).
`profiles.panorama-sg.com` and `credentials.panorama-sg.com` were not
mentioned in the Round 1 report's external-systems list — this is a
new finding from re-reading the legacy JSON-LD directly.

## Asset manifest — `web/src/data/assets-manifest.json`

See docs/ASSET-AUDIT.md.

## Content Collections — `web/src/content.config.ts`

Three collections (`news`, `pages`, `policies`), each with a real Zod
schema but **zero entries** — no legacy news, freeform page, or policy
document has been migrated into Markdown yet (bulk content migration
is explicitly out of scope for Version 1, project brief §31). The
`/news/` route and its dynamic `/news/[...slug]/` page prove the
collection wires up correctly (verified: `npm run build` produces
`/news/index.html` with an explicit "no news yet" state and zero
generated article pages, as expected for an empty collection).
