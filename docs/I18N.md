# Internationalisation Foundation

`astro.config.mjs` wires these into Astro's built-in i18n router
(`routing.prefixDefaultLocale: false`) — routing, not a hand-rolled
directory-duplication scheme like the legacy site's.

## Correcting a legacy ambiguity

The legacy site used bare `zh/` for **Traditional** Chinese and
`zh-cn/` for **Simplified** — a scheme that only reads correctly if
you already know which is which. The new locale codes make this
explicit: `zh-hant` (Traditional) and `zh-hans` (Simplified).
`web/src/data/redirects.json` encodes this remapping per-URL with a
note explaining why, so nothing about the correction is silent.

## Translation coverage

The shared interface strings are registered in
`web/src/i18n/locales/*.ts` and consumed by the global shell. Page copy is
kept in typed dictionaries so that terminology can be reviewed in one place:

- `content.ts` — home, shared catalogue, and common interface copy;
- `catalog.ts` — imprint and journal catalogue descriptions;
- `pages.ts` — the Research Institute page;
- `sections.ts` — publishing and books;
- `infrastructure.ts` — scholarly infrastructure;
- `group.ts` — about, governance, partnerships, and contact;
- `utility.ts` — search and announcements interface copy, including client-side search messages.

Those group-facing pages and shared navigation are translated for all 10
locales. Proper names, journal titles, DOI prefixes, and external platform
names remain in their registered form. Search and announcements interfaces are
also translated for all 10 locales. Journal-specific metadata and the
long-form policy/legal pages remain English canonical text until each
translation has received a separate editorial or legal review; localized routes
still preserve the correct language metadata and navigation.

## RTL

Arabic (`ar`) is the only `dir: 'rtl'` locale. `BaseLayout.astro` sets
`<html dir={current.dir}>` from the locale table, not a CSS class or
manual per-page flag. `web/src/styles/*.css` was written using logical
properties (`margin-inline-*`, `padding-inline`, `inset-inline-*`)
rather than physical ones (`margin-left`, `left: 0`) wherever
directionality could matter — verified by grep: no
`margin-left|margin-right|padding-left|padding-right|\bleft:\s|\bright:\s`
matches in `web/src/styles/`. Live proof at `/specimen/typography/`,
which renders real Arabic body copy in `dir="rtl"`.

## Deliberate boundaries

The site now generates locale-prefixed routes for all supported locales and
uses the same localized path when switching language. Some content types are
kept canonical in English until their terminology can be reviewed at the
right level of risk:

- journal-specific metadata and external journal-platform content;
- long-form editorial, ethics, open-access, privacy, terms, and accessibility
  policy text;
- brand-specific long-form editorial copy.

This is an editorial boundary, not a routing fallback: a localized page must
not imply that a legal or journal-specific translation has been approved when
it has not. These sections should be translated in dedicated review passes,
with legal text receiving an appropriate legal review before publication.
